# Strict macOS Keychain API token readback (#195)

**Parent:** newest successor Epic #10; origin Foundation #8, credentials #37, physical smoke #55.

The desktop's local agent bearer is generated from 32 bytes of `OsRng` and stored as exactly 43 ASCII characters of canonical, unpadded URL-safe Base64 in Keychain entry `service=com.gavindu.securityagent.desktop`, `account=agent-api-token`. New startup checks enforce that same representation on **existing** Keychain entries before constructing AgentState, starting HTTP or exposing native tool access. The check requires exact 43-byte length, URL-safe alphabet, strict decode length 32, and re-encoding identical to the original text. Invalid/truncated/overlong/padded/noncanonical entries produce a constant, redacted error. Existing entries are **never regenerated or overwritten silently** if malformed; no Keychain value enters logs, GitHub, a JSON file, or user-facing diagnostics. Missing entries keep the existing first-install generation path.

This is a narrow data-integrity and credential-format acceptance layer, not cryptographic proof of stored-token entropy: a malicious actor who can write the user's Keychain entry could encode chosen 32-byte data canonically. It does not implement credential scope separation, API token rotation or offboarding (#37), account-specific Keychain references (#18), physical Keychain smoke on a Mac Mini (#55), main branch ruleset (#149), or the native/HTTP read-response fence (#176).

**Mac operation:** An unexpected invalid entry stops app startup intentionally instead of silently replacing credentials. The operator must investigate and remediate Keychain state using approved support procedures; never paste the bearer in an issue, run log, screenshot or shell history. Do not delete a user credential as an automatic recovery path. Before deploying a migration to an older profile, validate that the existing desktop actually used the repository's 32-byte URL-safe generator; do not claim arbitrary legacy tokens remain supported.

**Acceptance gate:** Native Rust canonical/negative-shape unit tests, a Node test asserting readback refusal before state creation, an adversarial principal Rust/macOS AI source review, and all five exact-head CI jobs including native Apple Silicon strict mounted developer DMG verification and nonexpired artifact upload. Physical launch/restart acceptance remains separate in #55. ProtonLumo/lumo-desktop is an architectural reference only; no upstream code copied.
